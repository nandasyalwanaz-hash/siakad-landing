5. Role Pengguna

Empat Peran, Empat Dashboard

SIAKAD menerapkan Role Based Access Control (RBAC) menggunakan tabel hak_akses dan middleware CekHakAkses. Setelah login, pengguna diarahkan ke dashboard sesuai role: Admin, Operator, Dosen, atau Mahasiswa.

Role · 01 — Akses Tertinggi

Admin

Memiliki izin View, Create, Edit, dan Delete pada seluruh modul: dashboard, mahasiswa, dosen, mata kuliah, KRS, jadwal kuliah, absensi, nilai, fuzzy hasil, hingga hak akses pengguna. Bertanggung jawab atas seluruh data akademik dan konfigurasi sistem.

Role · 02 — Administrasi

Operator

Dashboard menampilkan ringkasan jumlah mahasiswa, dosen, mata kuliah, KRS, dan aktivitas akademik terbaru. Operator membantu proses administrasi akademik selama operasional sistem berlangsung.

Role · 03 — Pengajaran

Dosen

Dapat melihat data mahasiswa, mata kuliah, KRS, dan jadwal kuliah; menambah & memperbarui absensi, nilai, serta hasil evaluasi Fuzzy. Dashboard menampilkan total mata kuliah diampu, total mahasiswa, mahasiswa yang belum bernilai, dan jadwal mengajar hari ini. Dosen tidak memiliki hak hapus data maupun kelola hak akses.

Role · 04 — Mahasiswa

Mahasiswa

Dashboard menampilkan total SKS diambil, total mata kuliah, IPK, persentase kehadiran, jadwal hari ini, dan nilai terbaru — otomatis berdasarkan akun yang login. Mahasiswa hanya dapat melihat data akademiknya sendiri, tanpa izin tambah, ubah, atau hapus.

Catatan Implementasi

RoleSeeder mendefinisikan hak akses tiap role secara detail dan terbatas untuk Operator. Namun pada middleware CekHakAkses terdapat baris if ($role === 'Operator') { return $next($request); } — artinya pada implementasi yang berjalan, Operator justru dapat mengakses seluruh modul tanpa pembatasan tambahan, berbeda dari yang didefinisikan di seeder. Laporan ini mengikuti perilaku aplikasi yang sesungguhnya berjalan, bukan hanya isi seeder.

5.2 Mekanisme Hak Akses

Empat Jenis Permission

Setiap request diperiksa CekHakAkses berdasarkan role, modul, dan jenis aksi. Jika tidak memiliki izin, sistem menolak akses dan menampilkan pesan bahwa pengguna tidak berhak atas modul tersebut.

View

Izin untuk melihat data.

Create

Izin untuk menambahkan data.

Edit

Izin untuk memperbarui data.

Delete

Izin untuk menghapus data.

8. Arsitektur Sistem

Model–View–Controller (MVC)

Sistem menggunakan arsitektur MVC yang diterapkan oleh framework Laravel.

Client (Web / Flutter WebView)→ Laravel Routes→ Controller→ Middleware CekHakAkses→ FormRequest (Validasi)→ Model (Eloquent ORM)→ Database MySQL→ API Resource / Blade View→ Response ke Client

Pada setiap request, sistem melakukan autentikasi pengguna terlebih dahulu. Setelah login, middleware CekHakAkses memeriksa izin pengguna terhadap modul yang diakses. Jika memiliki izin, controller memproses data melalui model Eloquent dan mengembalikan hasil berupa halaman Blade maupun response JSON untuk REST API.

Struktur Database

Sembilan Entitas, Saling Terhubung

Gambaran Umum

  • 9 tabel entitas utama + tabel users
  • Relasi One-to-Many dan One-to-One
  • Foreign key terhubung antar modul akademik

Relasi Utama

  • Dosen → Mata Kuliah & Jadwal Kuliah
  • Mahasiswa → KRS & Absensi
  • Mata Kuliah → KRS, Jadwal, Absensi
  • KRS → Nilai & Fuzzy Hasil (One-to-One)
  • Hak Akses → Users
10. Dokumentasi API

Satu Pola untuk Sembilan Entitas

Base URL: /api/v1 — semua entitas mengikuti pola CRUD yang sama.

Seluruh endpoint API menggunakan format JSON dan menerapkan validasi menggunakan Laravel FormRequest. Setiap response dikembalikan dalam format yang konsisten sehingga mudah digunakan oleh aplikasi web maupun aplikasi mobile.

Contoh: Entitas Mahasiswa

GET/mahasiswaDaftar mahasiswa
POST/mahasiswaTambah mahasiswa
GET/mahasiswa/{id}Detail mahasiswa
PUT/mahasiswa/{id}Perbarui data
DELETE/mahasiswa/{id}Hapus data

Pola sama berlaku untuk: dosen, mata-kuliah, krs, nilai, absensi, jadwal-kuliah, hak-akses, fuzzy-hasil.

Contoh Response

{ "success": true, "message": "Mahasiswa berhasil ditambahkan.", "data": { "id": 1, "nim": "2101012345", "nama": "Siti Aminah", "prodi": "Sistem Informasi" } }
Langkah Instalasi

Menjalankan SIAKAD di Lokal

  • Clone/extract project ke folder Laragon.
  • Install dependency dengan composer install.
  • Salin .env.example menjadi .env, sesuaikan koneksi database.
  • Migrasi database dengan php artisan migrate.
  • Jalankan server dengan php artisan serve.
  • Verifikasi di http://127.0.0.1:8000.

13. Keamanan

Diuji dan Diverifikasi Menyeluruh

  • Autentikasi menggunakan sistem login Laravel
  • Middleware CekHakAkses untuk memverifikasi permission setiap pengguna
  • Validasi request menggunakan FormRequest
  • Penggunaan Eloquent ORM untuk meminimalkan risiko SQL Injection
  • Hak akses disimpan pada tabel hak_akses sehingga tiap role hanya mengakses modul yang diizinkan
14. Pengujian

Diverifikasi Menyeluruh

  • Pengujian login berdasarkan role pengguna
  • Pengujian hak akses menggunakan middleware CekHakAkses
  • Pengujian operasi CRUD pada seluruh modul sistem
  • Pengujian endpoint REST API menggunakan Postman
  • Pengujian validasi input menggunakan Laravel FormRequest
  • Pengujian akses aplikasi melalui browser dan aplikasi Android berbasis Flutter WebView
15. Kesimpulan

Satu Sistem, Seluruh Urusan Akademik.

SIAKAD berhasil dikembangkan sebagai Sistem Informasi Akademik berbasis Laravel yang menerapkan arsitektur MVC, Role Based Access Control (RBAC), REST API, dan metode Fuzzy Mamdani untuk evaluasi akademik mahasiswa. Sistem menyediakan dashboard yang berbeda untuk setiap role (Admin, Operator, Dosen, dan Mahasiswa), mendukung pengelolaan data akademik secara terintegrasi, serta dapat diakses melalui aplikasi web maupun aplikasi Android berbasis Flutter WebView. Pengujian menunjukkan bahwa fitur CRUD, autentikasi, hak akses, validasi data, dan layanan REST API berjalan sesuai kebutuhan sistem.
